    Chapter 4: Robot Navigation¶

    Robotics becomes truly useful when a robot can move from one place to another without being manually controlled. This ability is called navigation.

    A robot may have motors, wheels, sensors, and a controller, but if it cannot answer the following questions, it cannot navigate intelligently:

    1. Where am I?
    2. Where do I want to go?
    3. How do I reach the goal safely?
    4. What does the environment look like?
    5. Which part of the environment is still unknown?

    These questions form the foundation of robot navigation.

    4.1 What is Navigation?¶

    Navigation is the process of finding a way to reach a desired place.

    For humans, navigation may mean walking from one building to another, using Google Maps, or remembering a familiar route.

    For robots, navigation means:

    • understanding the environment,
    • estimating its own position,
    • planning a path,
    • avoiding obstacles,
    • and reaching a goal.

    A simple way to think about robot navigation is:

    Sense the environment → Understand position → Plan path → Move safely

    Example:

    A delivery robot in a hotel receives a command:

    Go to Room 405.

    To complete this task, the robot needs to:

    1. know where it currently is,
    2. know where Room 405 is,
    3. find a path through corridors,
    4. avoid people and obstacles,
    5. reach the room safely.

    4.2 Why Navigation is Important in Robotics¶

    Navigation is important because most useful robots must operate in real environments.

    Examples:

    Robot Navigation Need
    Hospital helper robot Move medicine or supplies between rooms
    Office delivery robot Carry documents or packages
    Hotel service robot Deliver items to guest rooms
    Museum guide robot Guide visitors through exhibits
    Autonomous car Drive safely on roads
    Warehouse robot Move goods between shelves
    Cleaning robot Cover floor area efficiently

    Without navigation, these robots would only be machines that can move. With navigation, they become autonomous systems.

    4.3 Main Parts of Robot Navigation¶

    Robot navigation is usually divided into four major problems.

    Path Planning: How do I get to my goal?
Localization: Where am I?
Mapping: Where have I been?
Exploration: Where haven’t I been?

    Each part answers a different question.

    4.3.1 Path Planning¶

    Path planning means finding a route from the robot's current position to a goal.

    Example:

    A robot is at the entrance of a building and wants to go to a classroom. It must decide which corridor to follow and where to turn.

    Path planning asks:

    How can I reach the goal?

    A good path may be:

    • short,
    • safe,
    • smooth,
    • fast,
    • energy efficient,
    • easy for the robot to follow.

    4.3.2 Localization¶

    Localization means estimating the robot's current position.

    It answers:

    Where am I?

    Example:

    A robot may know the map of a hospital, but it still needs to know whether it is near the reception, the elevator, or a patient room.

    Localization is not always easy because sensors are noisy. Wheels may slip, cameras may fail in low light, and GPS may not work indoors.

    4.3.3 Mapping¶

    Mapping means building a representation of the environment.

    It answers:

    What does the world look like?

    Example:

    A robot enters an unknown room. As it moves, it detects walls, open spaces, and obstacles. It gradually creates a map.

    Mapping is like memory. The robot remembers what it has already seen.

    4.3.4 Exploration¶

    Exploration means deciding where to go next when the environment is unknown.

    It answers:

    Where haven’t I been yet?

    Example:

    A rescue robot enters a damaged building. It does not know the full layout. It must choose unexplored areas to visit while building a map.

    4.4 Navigation Problem Characteristics¶

    Navigation becomes easier or harder depending on the environment.

    4.4.1 Known vs Unknown Environment¶

    A known environment means the robot already has a map.

    Example:

    A warehouse robot may already have a map of shelf locations.

    An unknown environment means the robot does not have a map before starting.

    Example:

    A robot enters a new building for the first time.

    Environment Type Meaning Example
    Known Map is available Robot in a mapped warehouse
    Unknown Map is not available Rescue robot in a collapsed building

    4.4.2 Static vs Dynamic Environment¶

    A static environment does not change much while the robot moves.

    Example:

    A closed empty classroom.

    A dynamic environment changes over time.

    Example:

    A hospital corridor where people, beds, and carts move.

    Environment Type Meaning Example
    Static Obstacles stay fixed Empty room
    Dynamic Obstacles move Crowded hallway

    Dynamic environments are harder because the robot must react to changes.

    4.4.3 Structured vs Unstructured Environment¶

    A structured environment has predictable shape and organization.

    Example:

    An office corridor with walls, doors, and rooms.

    An unstructured environment is irregular and less predictable.

    Example:

    A forest, construction site, or disaster area.

    Environment Type Meaning Example
    Structured Organized, predictable Office, hospital, classroom
    Unstructured Irregular, unpredictable Outdoor field, disaster area

    4.5 Path Planning: Conceptual Overview¶

    Path planning is not one single algorithm. It is a collection of methods.

    A robot may plan differently depending on:

    • whether the goal is visible,
    • whether it has a map,
    • whether obstacles are known,
    • whether obstacles are moving,
    • whether the robot needs the shortest path,
    • whether smoothness is important,
    • how much computation is available.

    For example, a small robot with a camera may simply move toward a visible ball. But an autonomous car needs a much more complex planner.

    4.6 Visual Homing¶

    Visual homing is a simple reactive navigation method.

    The robot uses vision to keep the goal centered in its camera view.

    The idea is:

    If the goal is left of center → turn left
If the goal is right of center → turn right
If the goal is centered → move forward

    This is called purely reactive navigation because the robot reacts directly to what it sees.

    Example: Robot Chasing a Ball¶

    Imagine a robot soccer player.

    • It sees the ball in its camera.
    • If the ball appears on the left side of the image, the robot turns left.
    • If the ball appears on the right side, the robot turns right.
    • If the ball is in the center, the robot moves forward.

    This method does not need a map. It only needs the goal to be visible.

    Advantages of Visual Homing¶

    • Simple to understand.
    • Fast reaction.
    • Does not require a map.
    • Useful when the target is visible.
    • Good for simple tasks like following a colored object.

    Limitations of Visual Homing¶

    • Fails if the goal is not visible.
    • Cannot plan around complex obstacles.
    • May get stuck behind walls or barriers.
    • Does not understand the full environment.

    4.7 Bug-Based Path Planning¶

    Bug-based planning is useful when the robot does not have a map but can sense obstacles locally.

    The robot knows the direction of the goal, but it does not know the full environment.

    The basic idea is:

    1. Move toward the goal.
    2. If an obstacle blocks the way, follow the obstacle boundary.
    3. When the path toward the goal becomes clear, leave the obstacle and move toward the goal again.

    This is called "bug-based" because the robot behaves like a small insect crawling around obstacles.

    Example: Robot in a Room with Unknown Obstacles¶

    Suppose a robot wants to reach a door but a table blocks the direct path.

    The robot:

    • starts moving toward the door,
    • touches or detects the table,
    • follows the edge of the table,
    • moves around it,
    • then continues toward the door.

    Advantages of Bug-Based Planning¶

    • Does not require a full map.
    • Works with local sensing.
    • Easy to understand.
    • Useful in unknown environments.

    Limitations of Bug-Based Planning¶

    • Path may be long.
    • Robot may waste time following obstacle boundaries.
    • Not always efficient.
    • Can be slow in cluttered environments.

    4.8 Global or Metric Path Planning¶

    Global path planning is used when the robot has a map of the environment.

    The robot knows:

    • its current position,
    • the goal position,
    • obstacle locations,
    • and free space.

    The goal is to find a good or optimal path.

    Usually, this means the shortest path, but it can also mean:

    • safest path,
    • smoothest path,
    • fastest path,
    • least energy path.

    Example: Google Maps Style Planning¶

    If you want to go from Banani to Badda, Google Maps may show different routes:

    • shortest route,
    • fastest route,
    • less traffic route,
    • easier route.

    A robot can do something similar if it has a map.

    4.9 Graph-Based Path Planning¶

    Many path planning methods convert the environment into a graph.

    A graph contains:

    • nodes,
    • edges,
    • costs.

    Example:

    Node = location or waypoint
Edge = possible movement between locations
Cost = distance, time, risk, or energy

    Then the robot searches the graph to find a path.

    Waypoints¶

    A path is often represented as a list of waypoints.

    Example:

    Start → Waypoint 1 → Waypoint 2 → Goal

    The robot follows these waypoints one by one.

    4.10 A* Path Planning¶

    A* is a popular global path planning algorithm.

    It is used when a map is available.

    A* tries to find a good path by considering:

    • how far the robot has already traveled,
    • and how close it appears to be to the goal.

    Conceptually, A* is smart because it does not search everywhere blindly. It prefers directions that seem promising.

    Example: Robot in a Grid Map¶

    Suppose a robot is in a grid world.

    • Some cells are free.
    • Some cells are occupied.
    • The robot starts in one cell.
    • The goal is another cell.

    A* searches through free cells and finds a path to the goal while avoiding occupied cells.

    Advantages of A*¶

    • Good for known maps.
    • Usually efficient.
    • Can find short paths.
    • Widely used in robotics and games.

    Limitations of A*¶

    • Needs a map.
    • If the environment changes, the plan may need to be recomputed.
    • Grid resolution affects performance.
    • A path may be geometrically short but not smooth for a real robot.

    4.11 Difference Between Path Planning Methods¶

    Method Map Needed? Sensor Type Best Situation Main Limitation
    Visual Homing No Camera/visual goal Goal is visible Fails when goal is hidden
    Bug-Based Planning No full map Local obstacle sensing Unknown environment with obstacles Can produce inefficient paths
    Global/A* Planning Yes Map + position estimate Known environment Needs a reliable map
    Frontier-Based Exploration Partial map Map + sensor updates Unknown environment exploration Needs mapping and planning together

    4.12 Localization¶

    Localization means estimating where the robot is.

    A robot may ask:

    Am I near the door?
Am I beside the wall?
Am I at the start position?
Am I close to the goal?

    Localization can be done using different methods.

    4.13 Dead-Reckoning¶

    Dead-reckoning estimates the robot's position by tracking its own movement.

    It starts from a known position and updates the position based on actions.

    Example:

    I started at the door.
I moved forward.
I turned right.
I moved forward again.
So I estimate that I am near the table.

    In robotics, dead-reckoning is also called:

    • odometry,
    • path integration.

    Example: Wheel Encoder Odometry¶

    A wheeled robot can estimate how far it has moved by measuring wheel rotation.

    If the wheels rotate forward, the robot assumes it moved forward.

    If one wheel rotates more than the other, the robot assumes it turned.

    Advantages of Dead-Reckoning¶

    • Does not require external landmarks.
    • Works even when the robot cannot see anything useful.
    • Simple and fast.
    • Useful for short-term motion tracking.

    Limitations of Dead-Reckoning¶

    • Error accumulates over time.
    • Wheel slip causes incorrect estimates.
    • Small errors become large after long travel.
    • It cannot correct itself without external sensing.

    Example:

    If a robot thinks it moved 1 meter but actually moved 0.9 meter because of wheel slip, the error remains. After many movements, the error becomes serious.

    4.14 Landmark-Based Localization¶

    Landmark-based localization uses known objects or signals in the environment.

    A landmark can be:

    • a visual marker,
    • a door,
    • a sign,
    • a radio tower,
    • a GPS satellite,
    • a QR code,
    • a wall feature,
    • a known corner.

    The robot compares what it senses with known landmark positions.

    Example: GPS¶

    A car uses GPS satellites as landmarks.

    By receiving signals from satellites, it estimates its location on Earth.

    Example: Indoor Robot with QR Codes¶

    A robot in a building may see QR markers placed on walls.

    If it detects a marker near Room 305, it can localize itself.

    Advantages of Landmark-Based Localization¶

    • Can correct accumulated motion error.
    • Useful for global position estimation.
    • Works well if landmarks are reliable and easy to detect.

    Limitations of Landmark-Based Localization¶

    • Needs known landmarks.
    • Fails if landmarks are hidden or misdetected.
    • GPS does not work well indoors.
    • Visual landmarks may fail in poor lighting.

    4.15 State Estimation¶

    State estimation combines motion information and sensing information.

    The main idea is:

    Motion gives prediction.
Sensing gives correction.
State estimation combines both.

    Dead-reckoning alone accumulates error. Landmark sensing alone may be noisy or unavailable. Combining them gives a better estimate.

    Example: Robot Moving in a Corridor¶

    A robot uses wheel odometry to estimate motion.

    But wheel odometry slowly drifts.

    Then the robot detects a known doorway or wall.

    The robot uses that sensor information to correct its position.

    Common State Estimation Methods¶

    Two common methods are:

    • Kalman Filter
    • Particle Filter / Monte Carlo Localization

    4.16 Kalman Filter Concept¶

    A Kalman Filter is used to estimate the robot's state when there is uncertainty.

    Conceptually, it works like this:

    1. Predict where the robot should be after moving.
    2. Sense the environment.
    3. Compare prediction with sensor measurement.
    4. Update the estimate.

    It is useful when the system and noise can be modeled in a structured way.

    Simple Example¶

    Suppose a robot believes it is 5 meters from a wall.

    Its sensor says it is 4.8 meters from the wall.

    The Kalman Filter combines both pieces of information and updates the estimate to something reasonable, such as 4.9 meters.

    4.17 Particle Filter Concept¶

    A Particle Filter represents many possible robot positions.

    Each possible position is called a particle.

    The robot updates these particles based on:

    • movement,
    • sensor measurements,
    • likelihood of being correct.

    Particles that match sensor data survive. Particles that do not match become less important.

    Simple Example¶

    A robot is lost in a building.

    It creates many guesses about where it might be.

    As it moves and observes walls, doors, and landmarks, incorrect guesses disappear. Eventually, most particles gather around the true location.

    4.18 Difference Between Localization Methods¶

    Method Main Idea Good For Weakness
    Dead-Reckoning Track movement from start Short-term estimation Error accumulates
    Landmark-Based Use known external references Correcting position Needs detectable landmarks
    Kalman Filter Combine motion and sensing mathematically Smooth continuous estimation Assumes structured uncertainty
    Particle Filter Maintain many possible location guesses Global localization and uncertainty More computationally expensive

    4.19 Mapping¶

    Mapping means building a memory of the environment.

    A map allows the robot to answer:

    Where are the walls?
Where are the obstacles?
Where is free space?
Which areas are unknown?

    Mapping is necessary when the environment is unknown or partially known.

    4.20 Occupancy Grid¶

    An occupancy grid represents the world as a grid of cells.

    Each cell can be:

    • occupied,
    • empty,
    • unknown.

    Typical meaning:

    Cell Type Meaning
    Occupied Something is there, such as wall or obstacle
    Empty Robot can move through it
    Unknown Robot has not observed it yet

    Occupancy grids are useful because they convert the continuous world into a simple map structure.

    Example: Room as Occupancy Grid¶

    Imagine a classroom divided into square cells.

    • Wall cells are occupied.
    • Open floor cells are empty.
    • Areas behind closed doors may be unknown.

    A robot can plan using this grid.

    4.21 Sensor Model¶

    A sensor model explains how raw sensor readings update the map.

    A sensor may return distance values, images, or depth information.

    The robot must convert these readings into grid cell states.

    Example: Depth Sensor¶

    Suppose a depth sensor measures an obstacle 3 meters away.

    Then:

    • cells before the obstacle are probably empty,
    • the cell at the measured obstacle distance is probably occupied,
    • cells behind the obstacle remain unknown because the sensor cannot see through it.

    This idea is important for building occupancy grid maps.

    4.22 Simple Occupancy Grid Mapping Algorithm¶

    A simple mapping process can be:

    1. Start with all cells unknown.
    2. Mark the robot's current cell as empty.
    3. Use sensor readings to mark visible cells.
    4. Mark free space as empty.
    5. Mark detected obstacles as occupied.
    6. Move to a neighboring empty cell.
    7. Repeat.

    This gradually builds a map of the environment.

    4.23 Exploration¶

    Exploration means choosing where to go next when the map is incomplete.

    Mapping answers:

    What have I already seen?

    Exploration answers:

    Where should I go to see more?

    A robot that explores randomly may waste time. A better robot chooses informative locations.

    4.24 Frontier-Based Exploration¶

    Frontier-based exploration is a common method for exploring unknown environments.

    A frontier is the boundary between known empty space and unknown space.

    A frontier cell is usually:

    an unknown cell next to an empty cell

    This means the robot can move near that area and discover new parts of the map.

    How Frontier-Based Exploration Works¶

    1. Build a partial map.
    2. Identify frontiers between known and unknown regions.
    3. Choose a frontier, often the closest one.
    4. Plan a path to that frontier.
    5. Move there and update the map.
    6. Repeat until no frontiers remain.

    When no frontiers remain, the map is considered complete for a finite environment.

    Example: Exploring a New Building¶

    A robot starts at the entrance.

    It sees a corridor and some rooms.

    The boundary between the seen corridor and unseen rooms becomes a frontier.

    The robot chooses one frontier and moves toward it.

    After reaching it, more of the building becomes visible.

    The robot continues until all reachable areas are explored.

    4.25 Difference Between Mapping and Exploration¶

    Topic Main Question Output
    Mapping What does the environment look like? A map
    Exploration Where should I go next to learn more? Next target or path

    Mapping builds the memory. Exploration decides how to improve that memory.

    4.26 SLAM¶

    SLAM stands for:

    Simultaneous Localization and Mapping

    SLAM means the robot localizes itself while building a map at the same time.

    This is difficult because:

    • to build a good map, the robot needs to know where it is,
    • but to know where it is, the robot often needs a map.

    This creates a chicken-and-egg problem.

    Example: Robot in an Unknown Office¶

    A robot enters an office for the first time.

    It does not know the map.

    It also does not know exactly where it is after moving.

    SLAM allows the robot to estimate its position and build the map together.

    4.27 Full Navigation Pipeline¶

    A practical navigation system may look like this:

    Sensors → Localization → Mapping → Planning → Control → Robot Motion

    Example:

    1. The robot uses LiDAR to sense walls.
    2. It estimates its position.
    3. It updates the occupancy grid.
    4. It plans a path to the goal.
    5. It sends velocity commands to the motors.
    6. It repeats the loop.

    4.28 Method Selection Guide¶

    Different situations require different methods.

    Situation Suitable Method
    Goal is visible and no map is needed Visual Homing
    No map, but robot can sense obstacles locally Bug-Based Planning
    Full map is available A* or Global Path Planning
    Robot needs to estimate position from wheel motion Dead-Reckoning
    Robot sees known objects or GPS Landmark-Based Localization
    Robot combines motion and sensing with uncertainty State Estimation
    Robot is building a map of free and occupied cells Occupancy Grid Mapping
    Robot must explore unknown space Frontier-Based Exploration
    Robot must build map and localize together SLAM

    Summary¶

    Robot navigation is the ability of a robot to move intelligently in an environment.

    The four major parts are:

    Path Planning → How do I get to my goal?
Localization → Where am I?
Mapping → Where have I been?
Exploration → Where haven’t I been?

    Important methods:

    • Visual Homing
    • Bug-Based Planning
    • A* / Global Planning
    • Dead-Reckoning
    • Landmark-Based Localization
    • Kalman Filter
    • Particle Filter
    • Occupancy Grid Mapping
    • Frontier-Based Exploration
    • SLAM

    A good robot often uses multiple methods together.

    For example:

    Occupancy Grid + Localization + A* + Frontier Exploration

    This combination allows a robot to map, localize, plan, and explore.

    Definition Questions¶

    Q1. Define robot navigation.¶

    Robot navigation is the ability of a robot to determine its location, understand the environment, plan a path, and move toward a goal.

    Q2. Define path planning.¶

    Path planning is the process of finding a route from the robot's current position to a desired goal.

    Q3. Define localization.¶

    Localization is the process of estimating where the robot is in the environment.

    Q4. Define mapping.¶

    Mapping is the process of building a representation of the environment.

    Q5. Define exploration.¶

    Exploration is the process of deciding where the robot should move next to discover unknown areas.

    Q6. Define visual homing.¶

    Visual homing is a reactive navigation method where the robot moves to keep a visible goal centered in its camera view.

    Q7. Define bug-based path planning.¶

    Bug-based path planning is a local navigation method where the robot moves toward the goal and follows obstacle boundaries when blocked.

    Q8. Define occupancy grid.¶

    An occupancy grid is a map representation where the environment is divided into cells, and each cell is marked as occupied, empty, or unknown.

    Q9. Define frontier.¶

    A frontier is a boundary between known empty space and unknown space in an occupancy grid.

    Q10. Define SLAM.¶

    SLAM stands for Simultaneous Localization and Mapping. It is the process of building a map while estimating the robot's position at the same time.

    Conceptual Questions¶

    Q1. Why is navigation more than just moving forward?¶

    Because a robot must know where it is, where it wants to go, what obstacles exist, and how to safely reach the goal.

    Q2. Why is dynamic environment navigation harder than static environment navigation?¶

    Because moving obstacles can change the path after the robot has planned it.

    Q3. Why does dead-reckoning accumulate error?¶

    Because every movement estimate may contain small errors, and these errors add up over time.

    Q4. Why is landmark-based localization useful?¶

    It can correct accumulated motion error by comparing sensor observations with known external references.

    Q5. Why is A* not suitable when the robot has no map?¶

    A* needs a map or graph to search. Without a map, it does not know which paths are free or blocked.

    Q6. Why is frontier-based exploration better than random exploration?¶

    Because it intentionally moves toward boundaries between known and unknown areas, so the robot discovers new space more systematically.

    Q7. Why is occupancy grid useful for robots?¶

    It gives a simple representation of free space, obstacles, and unknown regions, which can be used for mapping and planning.

    Q8. Why is SLAM difficult?¶

    Because the robot needs a map to localize, but it also needs localization to build a good map.

    Scenario-Based Questions¶

    Scenario 1¶

    A robot soccer player sees a ball in its camera. It turns left or right to keep the ball in the center and moves forward.

    What method is being used?

    Answer:

    Visual Homing

    Scenario 2¶

    A robot has no map. It moves toward a goal, detects an obstacle, follows the obstacle boundary, and then continues toward the goal.

    What method is being used?

    Answer:

    Bug-Based Path Planning

    Scenario 3¶

    A warehouse robot has a full map of the warehouse. It needs to find the shortest path from shelf A to shelf B.

    What method is most suitable?

    Answer:

    Global Path Planning / A* Path Planning

    Scenario 4¶

    A robot estimates its position by counting wheel rotations from a known starting point.

    What localization method is being used?

    Answer:

    Dead-Reckoning / Odometry

    Scenario 5¶

    A robot localizes itself by detecting QR codes placed on walls.

    What localization method is being used?

    Answer:

    Landmark-Based Localization

    Scenario 6¶

    A robot uses wheel odometry and wall distance measurements together to estimate its position more accurately.

    What method is being used?

    Answer:

    State Estimation

    Scenario 7¶

    A robot represents a room as a grid. Some cells are walls, some cells are free floor, and some cells are unknown.

    What representation is being used?

    Answer:

    Occupancy Grid

    Scenario 8¶

    A robot explores an unknown building. It always chooses the closest boundary between known empty space and unknown space.

    What exploration method is being used?

    Answer:

    Frontier-Based Exploration

    Scenario 9¶

    A robot enters an unknown building and builds a map while also estimating its own position.

    What concept is being used?

    Answer:

    SLAM

    Scenario 10¶

    A robot vacuum cleaner moves randomly and gradually covers parts of a room, but it often repeats the same area.

    Which problem is shown here?

    Answer:

    Inefficient exploration

    Scenario 11¶

    A delivery robot in a hospital has a map, but people are moving in the hallway. The robot must continuously avoid them.

    What type of environment is this?

    Answer:

    Dynamic environment

    Scenario 12¶

    A robot is navigating in a forest where the ground is irregular and obstacles are not arranged in a predictable way.

    What type of environment is this?

    Answer:

    Unstructured environment

    Scenario 13¶

    A robot can see the goal directly, but there is a wall between the robot and the goal. It keeps trying to move toward the visible direction and gets stuck.

    Which method is failing?

    Answer:

    Big Discussion Questions¶

    Q1. Compare visual homing, bug-based planning, and A* planning.¶

    Visual homing is the simplest and uses direct visual feedback. It works when the goal is visible. Bug-based planning does not need a map and can move around obstacles using local sensing. A* planning requires a map and searches for a good path globally.

    Q2. Explain why localization and mapping are connected.¶

    To build a correct map, the robot needs to know where it is. To know where it is, the robot often needs a map. This connection is the reason SLAM is important.

    Q3. Why is occupancy grid mapping suitable for exploration?¶

    Because it clearly separates the world into occupied, empty, and unknown cells. Unknown cells near empty cells become frontiers, which help the robot decide where to explore next.

    Q4. Which method would you choose for a hotel delivery robot and why?¶

    A hotel delivery robot should use localization, a known map, and global path planning such as A*. It may also use local obstacle avoidance because people and luggage can move in the hallway.

    Q5. Which method would you choose for a rescue robot in an unknown building and why?¶

    A rescue robot should use mapping, exploration, occupancy grid representation, frontier-based exploration, and SLAM because it does not know the environment beforehand.
