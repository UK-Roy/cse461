    Lecture 3¶

    Robot Architecture¶

    In previous lectures, we discussed how robots think and make decisions.

    Now we move to a more fundamental question:

    How is a robot physically built?

    A robot is not just software.
    It is a system composed of interconnected subsystems.

    Understanding this architecture helps us design, analyze, and debug robots properly.

    Robot Architecture Overview¶

    A robot can be divided into three major subsystems:

    1. Motion System
    2. Recognition System
    3. Control System

    These subsystems work together in a closed loop.

    Recognition → Control → Motion

    Motion System¶

    The motion system is responsible for physical movement.

    It includes:

    • Manipulator (links and joints)
    • End-effector
    • Actuators
    • Transmission mechanisms (belt, gear, linkage)

    This subsystem answers:

    How does the robot move?

    Example: Industrial Robotic Arm¶

    Consider a robotic arm in a car manufacturing plant.

    • The arm rotates at joints.
    • Motors drive the links.
    • Gears transmit torque.
    • A gripper holds metal parts.

    This entire structure is the motion subsystem.

    Why This Example Fits¶

    The robotic arm:

    • Has joints (manipulator structure)
    • Uses motors (actuators)
    • Uses gears (transmission)
    • Produces physical motion

    It directly demonstrates how the motion system converts energy into mechanical movement.

    Recognition System¶

    The recognition system allows the robot to sense its environment.

    It includes:

    • Sensors
    • Signal conversion (ADC)
    • Basic processing

    This subsystem answers:

    What is happening around me?

    Example: Warehouse Robot¶

    A warehouse robot uses:

    • Camera to detect shelves
    • LiDAR to measure distance
    • Encoders to measure wheel rotation

    These sensors allow it to understand position and obstacles.

    Why This Example Fits¶

    Without sensors:

    • The robot cannot detect shelves.
    • It cannot avoid obstacles.
    • It cannot localize itself.

    Recognition is the foundation of intelligent behavior.

    Control System¶

    The control system makes decisions and generates commands.

    It includes:

    • Digital controller
    • Algorithms
    • DAC
    • Amplifiers

    This subsystem answers:

    What should I do next?

    Example: Line-Following Robot¶

    A line-following robot:

    • Reads sensor values.
    • Controller computes error.
    • PID algorithm calculates correction.
    • Motor speed is adjusted.

    Why This Example Fits¶

    The controller:

    • Processes sensor data.
    • Makes decision.
    • Sends motor command.

    This demonstrates how control connects sensing and motion.

    System-Level Understanding¶

    A robot is not a single machine.

    It is an integration of:

    • Sensing (Recognition)
    • Thinking (Control)
    • Acting (Motion)

    If any subsystem fails:

    • No sensing → blind robot
    • No control → unstable robot
    • No motion → useless robot

    Good robotics engineering means designing these subsystems to work reliably together.

    Part 2 — Motion System¶

    In the architecture overview, we said:

    Motion system = how the robot physically moves.

    Now we break it down clearly.

    1. What Is the Motion System?¶

    The motion system converts energy into controlled movement.

    It includes:

    • Manipulator (structure)
    • End-effector (interaction tool)
    • Actuator (energy source)
    • Transmission (power transfer)

    Think of it like this:

    Energy → Actuator → Transmission → Link → End-effector → Motion

    2. Manipulator (Robot Structure)¶

    A simple 2-link arm:

    Link0--Joint1--Link1--Joint2--Link2

    Explain:

    • Links = rigid bodies
    • Joints = allow motion
    • Base = fixed reference

    The manipulator is the mechanical skeleton of the robot.

    A manipulator consists of:

    • Links
    • Joints (Revolute or Prismatic)
    • Base frame

    It defines (good to know):

    • Workspace
    • Reach
    • Degrees of Freedom

    Example: Human Arm¶

    Compare with human arm:

    • Shoulder → Joint 1
    • Elbow → Joint 2
    • Wrist → Joint 3
    • Hand → End-effector

    Why this example fits:

    The structure is identical: Rigid segments connected by joints producing motion.

    3. End-Effector¶

    The end-effector is the part that interacts with the environment.

    It is attached at the last link.

    Board:

    Manipulator → End-effector → Object

    Types¶

    1) Gripper type
    Two-finger or mechanical gripping.

    2) Anthropomorphic type
    Human-like robotic hand.

    Example: Pick-and-Place Robot¶

    In a factory:

    • Arm moves to location.
    • Gripper closes.
    • Object is lifted.
    • Object is placed.

    Why this example fits:

    The manipulator positions. The end-effector interacts.

    Without end-effector: The robot can move but cannot perform tasks.

    4. Actuators¶

    Now ask in class:

    What makes the joint rotate?

    Answer: Actuator.

    Theory¶

    An actuator converts energy into motion.

    Types:

    • Pneumatic (compressed air)
    • Hydraulic (pressurized fluid)
    • Electric (motor-based)

    Example Comparison¶

    Industrial heavy press: Hydraulic → high force.

    Light packaging robot: Pneumatic → fast, simple.

    Precision robot arm: Electric → accurate, easy control.

    Why these examples fit:

    Different applications require different force, precision, and speed.

    5. Transmission System¶

    Important question:

    If motor rotates very fast but weak, how do we increase torque?

    Answer: Transmission.

    Theory¶

    Transmission transfers motion from actuator to joint.

    Common types:

    • Belt
    • Chain
    • Gears
    • Link mechanisms

    Example¶

    Motor → Gear → Link

    Explain:

    Small motor gear drives bigger gear. Torque increases. Speed decreases.

    Why this example fits:

    Robots often require torque amplification at joints.

    6. Complete Motion Flow¶

    Now combine everything:

    Sensor says: move
    Controller computes angle
    Motor rotates
    Gear increases torque
    Link rotates
    Gripper moves

    That is motion subsystem in action.

    Key Takeaway¶

    Motion system = structure + energy + transmission.

    If any part fails:

    • No actuator → no motion
    • No transmission → weak motion
    • No manipulator → no structure
    • No end-effector → no task execution

    Part 3 — Actuators (Energy to Motion)¶

    We said earlier:

    Motion system needs energy.

    But what converts energy into movement?

    That device is called an actuator.

    1. What Is an Actuator?¶

    An actuator is a device that converts energy into mechanical motion.

    It produces:

    • Linear motion
    • Rotational motion

    Without actuators, the robot cannot move.

    2. Types of Actuators¶

    There are three main types used in robotics:

    1. Pneumatic
    2. Hydraulic
    3. Electric

    Each uses a different energy source.

    3. Pneumatic Actuator¶

    Uses compressed air.

    Air pressure pushes a piston. The piston moves linearly.

    Characteristics:

    • Fast
    • Simple
    • Clean
    • Light to medium load

    Example¶

    Compressed Air → Cylinder → Piston → Motion (See the image in the slide)

    Example: Packaging Machine¶

    In packaging systems:

    • Air pushes cylinder
    • Object is pushed quickly
    • Operation repeats rapidly

    Why this fits:

    Pneumatic systems are:

    • Fast
    • Cheap
    • Suitable for repetitive tasks

    But they are not good for:

    • Very high precision
    • Very heavy loads

    4. Hydraulic Actuator¶

    Uses pressurized fluid (oil).

    Fluid pressure creates very high force.

    Characteristics:

    • Very high torque
    • Heavy-duty
    • Powerful
    • Slower than pneumatic

    Example¶

    Pump → Pressurized Oil → Cylinder → Heavy Load Moves (See an animation in the slide)

    Example: Excavator Arm¶

    Construction machines use hydraulic cylinders.

    Why this fits:

    Excavator arms:

    • Lift tons of weight
    • Need strong force
    • Operate in harsh conditions

    Hydraulics provide: High force with controlled motion.

    5. Electric Actuator¶

    Uses electric motors.

    Converts electrical energy into rotation.

    Characteristics:

    • High precision
    • Easy control
    • Low maintenance
    • Clean operation

    Example¶

    Battery → Motor → Gear → Joint Rotation

    Example: Industrial Robot Arm¶

    Car manufacturing robot:

    • Uses electric motors
    • Precise angle control
    • Works with digital controller

    Why this fits:

    Electric actuators:

    • Integrate easily with control systems
    • Provide accurate positioning
    • Require less maintenance

    6. When Do We Choose Which?¶

    Ask students:

    If I need:

    • Very high force → Hydraulic
    • Very fast simple motion → Pneumatic
    • High precision control → Electric

    There is no “best” actuator. There is only “best for the application”.

    Key Engineering Insight¶

    Actuator choice depends on:

    • Required force
    • Required precision
    • Speed
    • Cost
    • Maintenance
    • Environment

    Part 4 — Motors¶

    In modern robotics, most systems use electric actuators.

    And electric actuators are powered by motors.

    So now we ask:

    How do different motors work?

    There are three common types:

    1. DC Motor
    2. Stepper Motor
    3. Servo Motor

    1. DC Motor¶

    Basic Theory¶

    A DC motor converts electrical energy into continuous rotational motion.

    Basic parts:

    • Stator (magnetic field)
    • Rotor (armature)
    • Commutator (maintains rotation)

    When current flows, magnetic interaction creates torque.

    Speed is controlled by: Changing the input voltage.

    Explanation¶

    Battery → Coil → Magnetic Field → Rotation

    Explain:

    Current + Magnetic field → Force → Rotation

    Example: Toy Car¶

    In a toy car:

    • Voltage applied
    • Motor spins continuously
    • Wheels rotate

    Why this fits:

    DC motor:

    • Simple
    • Continuous rotation
    • No position control by default

    Limitation¶

    DC motor:

    • Cannot directly control exact angle
    • Needs external feedback for precision

    2. Stepper Motor¶

    Basic Theory¶

    A stepper motor divides a full rotation into equal discrete steps.

    Each electrical pulse: → Moves the motor a fixed angle.

    Example: 1 pulse = 1.8°

    Characteristics:

    • Precise positioning
    • No feedback required (open-loop possible)
    • Holds position when energized

    Explanation¶

    Pulse 1 → Step
    Pulse 2 → Step
    Pulse 3 → Step

    Step by step movement.

    Example: 3D Printer¶

    3D printer uses stepper motors.

    Why this fits:

    3D printing requires:

    • Precise position
    • Controlled movement
    • No overshoot

    Stepper motors provide controlled discrete motion.

    Limitation¶

    • Can lose steps under heavy load
    • Less smooth at high speeds

    3. Servo Motor¶

    Basic Theory¶

    A servo motor is a closed-loop system.

    It includes:

    • Motor
    • Feedback sensor
    • Controller

    It continuously checks: Desired position vs Actual position.

    If error exists: It corrects automatically.

    Explanation¶

    Desired angle → Compare → Error → Adjust → Correct position

    This is feedback control.

    Example: Robotic Arm Joint¶

    Industrial robot joint:

    • Must reach exact angle
    • Must maintain torque
    • Must react to disturbance

    Why this fits:

    Servo motor:

    • High precision
    • Real-time correction
    • Stable under load

    4. Quick Comparison¶

    DC Motor: Continuous rotation, simple, cheap.

    Stepper Motor: Discrete steps, good positioning, open-loop.

    Servo Motor: Closed-loop, high precision, industrial use.

    Engineering Insight¶

    Choose motor based on:

    If you need:

    • Simple rotation → DC
    • Precise incremental positioning → Stepper
    • Accurate and stable industrial motion → Servo

    There is no universal best motor. Only application-driven selection.

    Part 5 — Control Hardware¶

    So far we discussed:

    • Motion system
    • Actuators
    • Motors

    But now a critical question:

    Who controls everything?

    Who reads sensors? Who sends motor commands? Who runs algorithms?

    That device is the control hardware.

    1. What Is Control Hardware?¶

    Control hardware is the physical computing unit that executes robot programs.

    It:

    • Reads sensor data
    • Runs control algorithms
    • Sends commands to actuators
    • Maintains timing and coordination

    Without control hardware, a robot cannot operate.

    2. Microcontroller (MCU)¶

    Theory¶

    A microcontroller is a compact integrated chip that contains:

    • CPU
    • Memory
    • Input/Output pins
    • Timers
    • ADC (Analog to Digital Converter)

    It is designed for:

    • Real-time control
    • Low power
    • Embedded systems

    Explanation¶

    Sensor → MCU → Motor Driver → Motor

    MCU sits in the middle.

    Example: Line-Following Robot¶

    A small robot:

    • IR sensor reads line
    • MCU calculates error
    • PWM signal sent to motor

    Why this fits:

    Microcontrollers:

    • Handle real-time tasks
    • Cheap
    • Low power
    • Ideal for small robots

    Characteristics¶

    • Deterministic timing
    • Fast response
    • Limited computing power
    • No operating system (usually)

    3. PLC (Programmable Logic Controller)¶

    Theory¶

    A PLC is an industrial controller designed for:

    • High reliability
    • Harsh environments
    • Deterministic operation
    • Safety compliance

    Used mainly in factories.

    Example: Factory Conveyor System¶

    A PLC:

    • Reads limit switches
    • Controls motors
    • Coordinates robotic arms
    • Runs continuously for years

    Why this fits:

    Factories need:

    • Reliability
    • Stability
    • Safety
    • Long-term operation

    PLC provides industrial robustness.

    Characteristics¶

    • Extremely reliable
    • Industrial-grade
    • Expensive
    • Not designed for AI

    4. SBC (Single Board Computer)¶

    Theory¶

    An SBC is a small full computer on a single board.

    Examples: - Raspberry Pi - Jetson Nano - Tinkerboard

    It includes:

    • CPU
    • RAM
    • GPU (sometimes)
    • Operating system

    It can run: - Linux - ROS - AI models

    Explanation¶

    Sensor → SBC → AI Model → Decision → Motor Command

    Example: Autonomous Robot with Vision¶

    A robot using:

    • Camera
    • Object detection
    • SLAM
    • Path planning

    Why this fits:

    AI and vision require:

    • High computation
    • GPU acceleration
    • Operating system

    Microcontrollers cannot handle heavy AI.

    5. Quick Comparison¶

    Microcontroller:

    • Real-time
    • Low power
    • Simple control tasks

    PLC:

    • Industrial automation
    • High reliability
    • Factory systems

    SBC:

    • High computation
    • AI and vision
    • Operating system based

    Engineering Insight¶

    Often robots use BOTH:

    SBC → High-level planning
    MCU → Low-level motor control

    Example:

    Camera → SBC → Path plan
    SBC → MCU → Motor command

    This layered architecture is very common in modern robotics.

    Practice Questions¶

    Scenario 1 — Simple Line Follower¶

    A small educational robot:

    • Uses 2 IR sensors
    • Controls 2 DC motors
    • Needs fast response
    • Runs on battery
    • No camera or AI

    Question: Which control hardware should be used?

    A) PLC
    B) Microcontroller
    C) SBC
    D) Hybrid (MCU + SBC)

    Answer: B) Microcontroller

    Why:

    • Real-time control needed
    • Low power
    • Simple logic
    • Cheap and compact

    Why NOT others:

    PLC: - Overkill - Expensive - Designed for industrial systems

    SBC: - Too much computation - Higher power consumption

    Hybrid: - Unnecessary complexity

    Scenario 2 — Factory Conveyor System¶

    A factory automation system:

    • Runs 24/7
    • Controls motors and safety switches
    • Must operate reliably for years
    • Safety compliance required

    Question: Best device?

    A) Microcontroller
    B) PLC
    C) SBC
    D) Arduino

    Answer: B) PLC

    Why:

    • Industrial reliability
    • Deterministic control
    • Designed for harsh environments
    • Long-term stable operation

    Why NOT others:

    Microcontroller: - Not industrial-grade - Limited protection

    SBC: - Operating system may crash - Not deterministic

    Arduino: - Educational tool, not industrial system

    Scenario 3 — Autonomous Delivery Robot¶

    A campus delivery robot:

    • Uses camera
    • Runs object detection
    • Performs SLAM
    • Path planning
    • Sends data to cloud

    Question: Best primary controller?

    A) PLC
    B) Microcontroller
    C) SBC
    D) Only DC motor driver

    Answer: C) SBC

    Why:

    • AI and vision require high computation
    • Needs operating system
    • Supports ROS, deep learning

    Why NOT others:

    PLC: - Not for AI

    Microcontroller: - Cannot handle heavy image processing

    Motor driver: - Not a controller

    Scenario 4 — Smart Robot Architecture¶

    A robot:

    • Uses camera for navigation
    • Uses wheel encoders
    • Needs real-time motor control
    • Runs AI and PID control

    Question: Best architecture?

    A) Only SBC
    B) Only Microcontroller
    C) SBC + Microcontroller
    D) PLC + SBC

    Answer: C) SBC + Microcontroller

    Why:

    SBC: - High-level planning - Vision - SLAM

    Microcontroller: - Low-level real-time motor control

    This layered architecture is common in robotics.

    Why NOT others:

    Only SBC: - OS delays may affect motor control

    Only MCU: - Cannot handle AI

    PLC + SBC: - Industrial unnecessary complexity

    Scenario 5 — Heavy Construction Robot¶

    A hydraulic robotic arm:

    • Lifts very heavy loads
    • Operates outdoors
    • Must be highly reliable
    • No AI required

    Question: Best control hardware?

    A) PLC
    B) SBC
    C) Arduino
    D) Stepper motor

    Answer: A) PLC

    Why:

    • Industrial-grade
    • High reliability
    • Designed for heavy machinery

    Why NOT others:

    SBC: - Not rugged enough

    Arduino: - Not industrial

    Stepper motor: - Not control hardware

    Scenario 6 — Cost-Constrained Startup Robot¶

    A startup builds a robot:

    • Requires moderate precision
    • No AI
    • Medium load
    • Budget extremely limited
    • Indoor usage only

    Question: Best cost-effective solution?

    A) PLC
    B) SBC
    C) Microcontroller
    D) Hybrid PLC + SBC

    Answer: C) Microcontroller

    Why:

    • Budget constraint
    • No AI needed
    • Moderate precision achievable
    • Low cost and power

    Why NOT others:

    PLC: - Too expensive

    SBC: - Unnecessary OS overhead

    Hybrid: - Over-engineered

    Scenario 7 — Safety-Critical Medical Robot¶

    A surgical assistant robot:

    • Requires high precision
    • Must avoid any unpredictable delays
    • Must comply with strict safety regulations
    • Uses image guidance
    • Controls actuators precisely

    Question: Best system architecture?

    A) Only SBC
    B) Only PLC
    C) SBC + Real-time microcontroller
    D) Arduino only

    Answer: C) SBC + Real-time microcontroller

    Why:

    SBC: - Handles image processing

    Microcontroller: - Ensures deterministic control - Real-time safety loop

    Why NOT others:

    Only SBC: - OS unpredictability risk

    Only PLC: - Limited for complex vision AI

    Arduino: - Not suitable for medical-grade precision
