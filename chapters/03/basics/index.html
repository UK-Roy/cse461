    Lecture 3¶

    Control System Basics¶

    Overview¶

    In this lecture, we introduce the fundamentals of control systems: - What is control theory
    - Open-loop vs closed-loop systems
    - Feedback and stability
    - Performance measures
    - Why controllers are needed
    - From diagrams to mathematical models

    1) What is Control Theory?¶

    Control theory studies how to control the behavior of a system to achieve a desired output.

    Intuition¶

    A control system always tries to solve this problem:

    • What I want (desired)
    • What I get (actual)
    • Adjust inputs to reduce the difference

    Example: Motor Speed Control¶

    • Desired speed = 3 rad/s
    • Actual speed = 2.2 rad/s

    Problem: The system is not behaving as expected.

    Control theory helps us design a system that reduces this error.

    Why this example works¶

    • Simple and visual
    • Shows mismatch clearly
    • Introduces the need for control immediately

    2) What is a Control System?¶

    A control system consists of:

    Input → Controller → Process → Output

    Components¶

    • Input: Desired value
    • Controller: Decision maker
    • Process: Physical system
    • Output: Actual result

    Example: Self-Balancing Robot¶

    • Input: Stay upright (angle = 0)
    • Controller: PID
    • Process: Robot + motors
    • Output: Actual angle

    Why this example works¶

    • Strong robotics connection
    • Easy to visualize
    • Maps directly to real systems

    3) Open Loop Control¶

    Open-loop systems do not use feedback.

    They apply input and never check the output.

    Example¶

    • Apply voltage to motor
    • Assume it reaches desired speed
    • No measurement is taken

    Problem¶

    Desired = 3 rad/s
    Actual = 2.2 rad/s

    Error remains uncorrected.

    Why this example works¶

    • Clearly shows limitation
    • Demonstrates why feedback is needed

    Real-life Example¶

    Fan speed regulator: - You set speed
    - Load changes → speed changes
    - System does not correct itself

    4) Closed Loop Control (Feedback)¶

    Closed-loop systems use feedback:

    Measure → Compare → Correct

    Key Idea¶

    The system continuously checks: "Am I doing the right thing?"

    Example: Thermostat¶

    • Desired temperature = 25°C
    • Current temperature = 22°C
    • Heater turns ON

    System keeps adjusting until the desired value is reached.

    Why this example works¶

    • Very familiar system
    • Clearly shows feedback behavior

    Robotics Example¶

    Self-balancing robot:

    • Sensor measures angle
    • Controller adjusts motor
    • Robot stays upright

    5) Feedback System Components¶

    A feedback system includes:

    • Controller
    • Sensor
    • Actuator
    • Feedback
    • Error signal

    Example Mapping¶

    Component Example
    Sensor IMU
    Controller PID
    Actuator Motor
    Error Desired - Actual

    6) Stability¶

    A system is stable if its output remains bounded over time.

    Example: Balancing a Pencil¶

    • Disturb the pencil
    • It wobbles
    • Returns to position

    Why this example works¶

    • Easy to visualize
    • Shows recovery behavior clearly

    7) System Performance¶

    We evaluate a system using:

    • Transient response
    • Steady-state response

    7.1 Transient Response¶

    Behavior before the system settles.

    Example: Light Switch¶

    • Turn ON
    • Light gradually stabilizes

    Why this example works¶

    • Everyday experience
    • Clearly shows transition phase

    7.2 Steady-State Response¶

    Behavior after the system stabilizes.

    Example: Elevator¶

    • Accelerates
    • Moves at constant speed
    • Stops

    Why this example works¶

    • Real system
    • Clearly shows steady operation

    8) Key Performance Metrics¶

    Rise Time (Tr)¶

    Time to go from 10% → 90% of final value

    • Indicates speed of response

    Peak Time (Tp)¶

    Time to reach first maximum peak

    • Shows how quickly system reacts

    Maximum Overshoot (Mp)¶

    Amount system exceeds final value

    • Indicates oscillation

    Settling Time (Ts)¶

    Time to stabilize within tolerance

    • Indicates stability speed

    9) Steady-State Error¶

    ess = desired - actual

    Types¶

    • Zero error → perfect system
    • Finite error → small difference
    • Infinite error → system fails

    Example¶

    • Desired = 3
    • Actual = 2.9

    Small steady-state error exists.

    10) Important System Examples¶

    Example 1: Drone Stabilization¶

    Situation: - Wind disturbs drone

    Desired Behavior¶

    • Low rise time → fast reaction
    • Low peak time → quick correction
    • Small overshoot → acceptable

    Why this example works¶

    • Safety-critical system
    • Requires fast response
    • Real-world robotics scenario

    Example 2: Chemical Decay¶

    Situation: - Substance decays over time

    Desired Behavior¶

    • Slow response
    • Smooth decay
    • No oscillation

    Why this example works¶

    • Opposite of drone example
    • Shows not all systems need speed

    Key Insight¶

    Different systems require different behaviors.

    11) Why Do We Need a Controller?¶

    Problem: Systems do not naturally behave as desired.

    Solution¶

    Introduce a controller to:

    • Reduce error
    • Improve stability
    • Adjust response

    Example¶

    PID controller: - Adjusts input
    - Improves system performance

    12) Gain¶

    Gain = Output / Input

    Meaning¶

    Gain shows how strongly the system responds.

    Example¶

    Input = 2
    Output = 10

    Gain = 5

    Why it matters¶

    Changing gain affects:

    • Speed
    • Overshoot
    • Stability

    13) From Block Diagram to Mathematics¶

    Block diagrams give intuition, but we need math to:

    • Predict behavior
    • Analyze systems
    • Design controllers

    14) Transfer Function¶

    H(s) = Y(s) / X(s)

    Meaning¶

    Relationship between input and output.

    Why useful¶

    • Simplifies analysis
    • Avoids complex differential equations
    • Works in frequency domain

    15) Why Move to Frequency Domain?¶

    Problem (Time Domain)¶

    • Signals are mixed
    • Hard to analyze

    Example: Sensor Noise¶

    IMU sensor gives: - real motion
    - vibration noise
    - disturbances

    All mixed together.

    Solution¶

    Frequency domain separates signals.

    Why this example works¶

    • Real robotics problem
    • Shows limitation of time domain
    • Motivates frequency analysis

    Final Summary¶

    A control system:

    • observes the system
    • compares with desired behavior
    • adjusts inputs

    Key Ideas¶

    • Open loop → no correction
    • Closed loop → uses feedback
    • Performance matters
    • Different systems need different responses
    • Controllers improve behavior
    • Math helps analyze systems

    Big Picture¶

    Control systems allow us to:

    • make systems stable
    • improve accuracy
    • design intelligent robots

    Self Check Quiz¶

    Part A — Conceptual MCQ¶

    Choose the BEST answer.

    Q1¶

    A motor is given a fixed voltage and runs without measuring its actual speed.
    Which type of system is this?

    A) Closed-loop
    B) Feedback system
    C) Open-loop
    D) Adaptive system

    Answer: C
    Explanation: No feedback is used, so the system cannot correct errors.

    Q2¶

    Which of the following BEST describes feedback?

    A) Sending input to system
    B) Measuring output and using it for correction
    C) Increasing system gain
    D) Reducing system speed

    Answer: B
    Explanation: Feedback uses output information to adjust the input.

    Q3¶

    Why is closed-loop control preferred over open-loop?

    A) It is cheaper
    B) It is simpler
    C) It corrects errors automatically
    D) It removes sensors

    Answer: C
    Explanation: Closed-loop systems adjust input based on output, reducing error.

    Q4¶

    Which system requires the FASTEST response?

    A) Chemical decay
    B) Temperature control
    C) Drone stabilization
    D) Water tank filling

    Answer: C
    Explanation: Drone must react quickly to disturbances to avoid crashing.

    Q5¶

    Which system requires a SLOW and smooth response?

    A) Self-balancing robot
    B) Drone stabilization
    C) Chemical decay
    D) Motor speed control

    Answer: C
    Explanation: Sudden changes are undesirable in chemical systems.

    Q6¶

    What does gain represent?

    A) Energy consumption
    B) System stability
    C) Output-to-input ratio
    D) Sensor accuracy

    Answer: C
    Explanation: Gain = Output / Input.

    Q7¶

    A system shows large oscillations before settling. What is most likely high?

    A) Rise time
    B) Overshoot
    C) Steady-state error
    D) Gain = 0

    Answer: B
    Explanation: Oscillations indicate high overshoot.

    Q8¶

    Which parameter tells how fast a system initially reacts?

    A) Settling time
    B) Steady-state error
    C) Rise time
    D) Gain

    Answer: C
    Explanation: Rise time measures initial speed of response.

    Q9¶

    A system reaches the desired value but always stays slightly below it.
    This is:

    A) Infinite error
    B) Zero error
    C) Finite steady-state error
    D) Instability

    Answer: C
    Explanation: A constant difference remains.

    Q10¶

    Why do we move to frequency domain?

    A) To increase system speed
    B) To avoid sensors
    C) To separate signals and simplify analysis
    D) To remove equations

    Answer: C
    Explanation: Frequency domain helps separate noise and simplifies analysis.

    Part B — Short Conceptual Questions¶

    Q1¶

    What is the main limitation of open-loop systems?

    Answer:
    They cannot correct errors because they do not use feedback.
    If the output differs from desired value, the system cannot adjust itself.

    Q2¶

    Explain feedback in one sentence.

    Answer:
    Feedback is the process of measuring system output and using it to adjust the input to reduce error.

    Q3¶

    Why is feedback important in robotics?

    Answer:
    Because real-world environments change constantly, feedback allows robots to adapt and maintain correct behavior.

    Q4¶

    What is stability?

    Answer:
    Stability means the system output remains bounded and eventually settles after disturbances.

    Q5¶

    Give one real-life example of closed-loop control.

    Answer:
    Thermostat: It measures temperature and adjusts heating/cooling accordingly.

    Q6¶

    Why is rise time important for drones?

    Answer:
    Because drones must react quickly to disturbances (like wind) to maintain stability.

    Q7¶

    Why is overshoot undesirable in some systems?

    Answer:
    Because exceeding the desired value can cause damage or unsafe behavior (e.g., chemical systems, temperature control).

    Q8¶

    What is steady-state error?

    Answer:
    The difference between desired and actual output after the system has settled.

    Q9¶

    Why do different systems require different responses?

    Answer:
    Because each system has different goals — some require fast response (drone), others require smooth response (chemical process).

    Q10¶

    Why do we need controllers?

    Answer:
    Because natural system behavior is often not ideal; controllers help adjust input to achieve desired performance.

    Part C — Thinking Questions (Optional for Class Discussion)¶

    Q1¶

    What could happen if a drone has very high overshoot?

    Answer:
    It may become unstable and crash due to excessive oscillations.

    Q2¶

    Can a system be fast but unstable? Explain.

    Answer:
    Yes. A system may respond quickly (low rise time) but overshoot excessively and oscillate, making it unstable.

    Q3¶

    Why is a purely reactive system not always sufficient?

    Answer:
    Because it lacks long-term planning and may get stuck or fail to reach goals.

    Q4¶

    Why is a purely planning-based system not always practical?

    Answer:
    Because real environments change, and heavy planning can be too slow.

    Key Takeaway¶

    A good control system balances: - speed
    - stability
    - accuracy

    And uses feedback to adapt to real-world changes.
